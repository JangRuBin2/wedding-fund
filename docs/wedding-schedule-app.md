# 결혼 일정 앱 기획 (가칭: 봄날)

> 결혼 준비 **일정**만 둘이 같이 관리하는 앱이에요. 모아봄(wedding-fund)의 결혼준비 탭에서 잘 쓰던 기능을 가져오고, 공용 자산 관리(가계부)는 뺐어요.
> 참고: 모아봄 코드(`server/src/app/wedding/*`, `server/src/lib/checklist.ts`, `server/src/lib/wedding-meta.ts`), 모아봄 결혼준비 기획(`docs/wedding-planning.md`), 손그림 스케치(캘린더 → `+` → 이벤트 만들기 → 이벤트 상세)
>
> 이 문서는 기획까지만 다뤄요. 개발은 이 문서를 확정한 뒤에 시작해요.

## 요약

- **하는 일**: 결혼 준비 이벤트(양가 인사 → 웨딩홀 계약 → … → 신혼여행)를 캘린더와 리스트로 보고, 이벤트마다 체크리스트와 메모를 둘이 같이 채워요.
- **빼는 것**: 결제 알림 자동 수집, 가계부 내역, 목표 저축, 소비 패턴, 주간 피드백, 예산 배분, 결제 금액 합계. 돈은 '언제 내야 하는지'라는 **일정**으로만 다뤄요.
- **가장 큰 변화**: 모아봄은 한 화면 안에서 보면서 바로 적었어요. 이 앱은 **보기 화면과 작성 화면을 나눠요.** 보기 화면에는 입력 칸이 없고, `+`나 `수정`을 누르면 작성 화면으로 넘어가요. 저장하면 보던 화면으로 돌아와요.
- **1차(MVP)**: 캘린더·리스트 보기, 이벤트 만들기·수정, 20개 기본 이벤트와 추천 일정, 이벤트별 체크리스트·메모, 누가 체크했는지 기록, 둘이 같이 쓰기.

## 1. 만드는 이유

모아봄 결혼준비 탭에서 매주 쓰인 건 가계부보다 **이벤트, 체크리스트, 캘린더** 쪽이었어요. 그런데 가계부 앱 안에 있어서,
- 결혼 준비만 보고 싶은 사람(특히 결제 알림 수집을 안 쓰는 사람)에게도 가계부 설정과 홈 화면이 먼저 보이고,
- 아이폰 사용자는 결제 수집을 못 쓰는데 앱 전체가 그 기능을 중심으로 짜여 있어요.

그래서 일정 기능만 떼어 내 가벼운 앱으로 만들어요.

## 2. 범위

| 모아봄 기능 | 이 앱 | 비고 |
|---|---|---|
| 이벤트(20단계 + 직접 추가), 완료 체크, 체크한 사람 | **가져옴** | 핵심 |
| 결혼식 날짜 기준 추천 일정 채우기 | **가져옴** | 결혼식 날짜는 이 앱의 '우리 정보'에서 정해요 (모아봄은 목표 날짜를 썼어요) |
| 이벤트 안 체크리스트, 할 일별 날짜, 추천 할 일 넣기, 행정·혜택 할 일 | **가져옴** | |
| 이벤트 메모 | **가져옴** | 스케치의 '메모(사진)' → 2차에서 사진 첨부 |
| 캘린더(이벤트·할 일·결제 예정 점 표시) | **가져옴** | 결제 점 대신 '돈 낼 날' 일정으로 |
| 곧 할 일(30일 안, 밀린 것 먼저), D-day | **가져옴** | |
| 카카오 로그인, 관리자 승인, '이 기기는 누구' | **가져옴** | |
| 매일 아침 '오늘의 팁' 알림 | **바꿔서** | '오늘·내일 할 일' 알림으로 |
| 예산 구분(예식·스드메 …)과 색 | **바꿔서** | 이벤트 **카테고리**로만 써요(색 구분, 필터). 금액은 없어요 |
| 이벤트 결제관리(금액·결제자·결제 방식) | **바꿔서** | 금액 합계는 빼고 '돈 낼 날' 일정만 남겨요. 아래 3-4 참고 |
| 결제 알림 수집, 내역, 패턴, 목표, 주간 피드백, 하루 권장액 | **뺌** | 공용 자산 관리 |
| 예산 배분 슬라이더, 세부 예산표, 사용량 막대 | **뺌** | 공용 자산 관리 |
| 안드로이드 네이티브 앱(알림 리스너) | **뺌** | 웹 앱(PWA)으로 충분해요. 홈 화면에 추가하면 앱처럼 쓰고, 아이폰도 같아요 |

**확인이 필요한 결정**: '돈 낼 날'(계약금·잔금일)을 일정으로 남길지, 돈 이야기를 완전히 뺄지. 이 문서는 **남기는 쪽**으로 썼어요. 웨딩홀 잔금일처럼 놓치면 곤란한 날짜라서요. 빼기로 하면 3-4와 데이터 모델의 `kind = PAYMENT`만 지우면 돼요.

## 3. 핵심 원칙: 보기와 작성 분리

### 3-1. 규칙

1. **보기 화면에는 입력 칸이 없어요.** 텍스트 입력, 날짜 선택, 저장 버튼은 작성 화면에만 둬요.
2. 보기 화면에서 바로 할 수 있는 건 **한 번 눌러서 끝나는 동작**뿐이에요. 완료 체크, 체크 해제, '냈어요' 같은 것들이요. 누르자마자 화면에 반영하고 저장은 뒤에서 해요(모아봄의 `OptimisticCheck` 방식).
3. 보기 화면의 `+`(추가)와 `수정`은 작성 화면으로 넘어가는 링크예요.
4. 작성 화면은 한 가지만 해요. 맨 위에 `‹ 돌아갈 곳`과 화면 제목, 아래에 입력 칸, 맨 아래에 큰 `저장` 버튼이 있어요.
5. 저장하면 **보던 화면으로 돌아가요.** 새로 만든 이벤트는 그 이벤트의 보기 화면으로 가요.
6. **삭제는 수정 화면 맨 아래**에만 둬요. 보기 화면에서 실수로 지우지 않게요.
7. 작성 화면을 그냥 닫거나 뒤로 가면 아무것도 바뀌지 않아요(취소 = 뒤로 가기).

### 3-2. 왜 나누는가

- 보기 화면이 짧아지고 읽기 쉬워져요. 모아봄의 이벤트 상세는 체크리스트, 메모 입력, 결제 입력 폼이 한 화면에 있어서 스크롤이 길었어요.
- 입력 중인 내용과 저장된 내용이 섞이지 않아요. 메모 칸에 적다가 저장을 안 누르고 나가면 사라지는 문제가 있었어요.
- 둘이 같이 볼 때, 보기 화면은 항상 '저장된 상태'라 서로 같은 걸 봐요.
- 작성 화면만 따로 다듬을 수 있어요(키보드에 가리지 않는 레이아웃, 자동 포커스, 추천 칩).

## 4. 화면 구성

스케치 흐름: **캘린더 → `+` → 이벤트 만들기(이름, 카테고리: 스드메·예식장 …) → 이벤트 상세(체크리스트 0/0 · 추가하기, 메모(사진), 돈 낼 날)**

### 4-1. 화면 목록

| 구분 | 주소 | 화면 | 바로 하는 동작 / 넘어가는 곳 |
|---|---|---|---|
| 보기 | `/` | **홈**: D-day, 진행 n/20, 곧 할 일(30일 안, 밀린 것 먼저) | 할 일 체크 / 이벤트 보기 |
| 보기 | `/events` | **이벤트**: `[리스트 · 캘린더]` 전환, 카테고리 필터 칩 | 이벤트 완료 체크 / `+` → `/events/new` |
| 보기 | `/events/[id]` | **이벤트 상세**: 날짜, 카테고리, 체크리스트 n/m, 메모, 돈 낼 날 | 할 일 체크, '냈어요' / `수정`, `+ 할 일`, `+ 돈 낼 날`, `메모 쓰기` |
| 작성 | `/events/new` | 이벤트 만들기: 이름, 카테고리, 날짜(선택) | 저장 → 만든 이벤트 상세 |
| 작성 | `/events/[id]/edit` | 이벤트 수정: 이름, 카테고리, 날짜 + 맨 아래 삭제 | 저장 → 이벤트 상세, 삭제 → 이벤트 목록 |
| 작성 | `/events/[id]/memo` | 메모 쓰기: 큰 글 칸 하나 (2차: 사진) | 저장 → 이벤트 상세 |
| 작성 | `/events/[id]/tasks/new` | 할 일 추가: 내용, 날짜(선택), 추천 할 일 칩 | 저장 → 이벤트 상세 |
| 작성 | `/tasks/[id]/edit` | 할 일 수정: 내용, 날짜 + 삭제 | 저장 → 이벤트 상세 |
| 작성 | `/events/[id]/payments/new` | 돈 낼 날 추가: 무엇(계약금·잔금), 날짜, 메모 | 저장 → 이벤트 상세 |
| 작성 | `/payments/[id]/edit` | 돈 낼 날 수정 + 삭제 | 저장 → 이벤트 상세 |
| 보기 | `/settings` | **설정**: 결혼식 날짜, 우리 둘 이름, 알림, 로그인 계정 | 각 항목 → 작성 화면 |
| 작성 | `/settings/wedding` | 결혼식 날짜·장소 | 저장 → 설정 |
| 시작 | `/start` | 처음 쓰는 사람: 결혼식 날짜 → "20개 이벤트로 시작" → "추천 일정 채우기" | 끝나면 홈 |

아래 탭은 `홈 · 이벤트 · 설정` 3개예요.

### 4-2. 이벤트 상세 (보기)

```
‹ 이벤트                                   수정
┌─────────────────────────────────────────┐
│ 이벤트 5 · 스드메                          │
│ 헤어변형·헬퍼 관련                [완료]   │
│ 3월 14일 · D-42                           │
└─────────────────────────────────────────┘
체크리스트 1/3                        + 할 일
 ☑ 헬퍼 이모님 연락처 받기   지은 · 2/20
 ☐ 헤어변형 시안 고르기      3/1 · D-29   ›
 ☐ 추가금 확인                            ›
메모                                  메모 쓰기
 머리 시안 어떻게 하지? 업체에 물어볼 것
돈 낼 날                              + 추가
 ● 헬퍼비 잔금   3월 14일 · D-42   [냈어요]
```

- 할 일 줄의 체크 상자는 바로 체크돼요. 줄의 나머지 부분을 누르면 할 일 수정 화면으로 가요.
- 메모가 없으면 "아직 메모가 없어요"와 `메모 쓰기` 버튼만 보여요.

### 4-3. 이벤트 만들기 (작성)

```
‹ 취소              이벤트 만들기
이름        [ 드레스 투어                ]
카테고리    (예식) (스드메●) (예물·예단) (신혼여행) (신혼집) (기타)
날짜        [ 2027-03-14 ]   □ 날짜 미정
                       [ 저장 ]
```

- 이름 칸에 자동 포커스. 자주 쓰는 이름은 자동완성(드레스 투어, 상견례, 청첩장 …).
- 캘린더에서 날짜를 누른 상태로 `+`를 누르면 그 날짜가 미리 채워져요(`/events/new?date=2027-03-14`).

### 4-4. 돈 낼 날

모아봄 결제관리에서 금액·결제자·결제 방식·합계를 빼고 **날짜와 이름만** 남긴 거예요.
- 보기: 캘린더에 카테고리 색 점으로 표시, 홈의 '곧 할 일'에도 같이 나와요.
- '냈어요'를 누르면 완료 표시만 해요. 금액을 적고 싶으면 메모 칸을 써요.

## 5. 데이터 모델 (초안)

모아봄의 `WeddingStep` / `WeddingTask` / `WeddingPayment`를 거의 그대로 가져오고, 돈 관련 필드를 뺐어요.

```prisma
/// 결혼식 정보 (레코드 하나)
model Wedding {
  id        Int       @id @default(1)
  date      DateTime? // 결혼식 날짜. 추천 일정 계산 기준
  place     String?
  updatedAt DateTime  @updatedAt
}

/// 준비 이벤트 (20개 기본 + 직접 추가)
model Event {
  id          String    @id @default(cuid())
  order       Int
  title       String
  category    String    @default("기타")  // 예식 | 스드메 | 예물·예단 | 신혼여행 | 신혼집 | 기타
  date        DateTime?
  memo        String?
  hint        String?                     // 템플릿 안내 (하객 수 → 웨딩홀·청첩장)
  done        Boolean   @default(false)
  doneAt      DateTime?
  doneBy      String?
  templateKey String?   @unique
  tasks       Task[]
  dues        Due[]
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
}

/// 이벤트 안 할 일
model Task {
  id        String    @id @default(cuid())
  event     Event     @relation(fields: [eventId], references: [id], onDelete: Cascade)
  eventId   String
  section   String?   // 상견례 / 드레스 피팅 / 행정·혜택 …
  content   String
  date      DateTime?
  done      Boolean   @default(false)
  doneAt    DateTime?
  doneBy    String?
  createdBy String?
  sortOrder Int       @default(0)
  createdAt DateTime  @default(now())
  @@index([eventId])
}

/// 돈 낼 날 (계약금·중도금·잔금). 금액은 저장하지 않아요
model Due {
  id        String    @id @default(cuid())
  event     Event     @relation(fields: [eventId], references: [id], onDelete: Cascade)
  eventId   String
  title     String    // 잔금, 계약금 …
  date      DateTime
  memo      String?
  done      Boolean   @default(false)
  doneAt    DateTime?
  doneBy    String?
  @@index([eventId])
}

/// 카카오 로그인 사용자 (모아봄 User와 같음)
model User { /* id, kakaoId, name, role, status, createdAt, lastLoginAt */ }

/// 푸시 알림 구독 (2차)
model PushSubscription { id String @id @default(cuid()); userId String; endpoint String @unique; keys Json }
```

- 기본 데이터는 모아봄 `lib/checklist.ts`의 `WEDDING_STEPS`(20단계, 추천 일정 offset), `SUGGESTED_TASKS`(추천 할 일, 행정·혜택)를 그대로 써요. 각 단계에 카테고리만 붙여요(예: s03 스드메·본식 스냅 계약 → 스드메, s07 신혼여행 예약 → 신혼여행).
- 카테고리 이름과 색은 모아봄 `WEDDING_CATEGORIES`에서 금액 비율(`ratio`)만 빼고 가져와요.

## 6. 같이 쓰기

- 카카오 로그인 → 처음 들어온 사람이 관리자, 상대는 관리자가 승인(모아봄과 같음). 로그인한 이름이 그대로 '체크한 사람'이 돼요.
- 카카오 키를 안 넣으면 비밀번호 하나로 잠그고, 기기마다 '이 기기는 누구'를 골라요(모아봄의 `moabom_me` 쿠키 방식).
- 둘이 같은 걸 동시에 고칠 일은 드물어서, 나중에 저장한 쪽이 남아요. 보기 화면은 열 때마다 서버에서 새로 읽어요.

## 7. 알림

- **1차**: 없음. 홈의 '곧 할 일'로 대신해요.
- **2차**: 웹 푸시(PWA). 매일 아침 "오늘 할 일 2개 · 내일 잔금일 1개". 체크한 사람의 상대에게 "지은님이 '드레스 투어 예약'을 끝냈어요"(끌 수 있게).
- 아이폰은 홈 화면에 추가한 PWA에서만 웹 푸시가 와요(iOS 16.4 이상). 설정 화면에 안내를 넣어요.

## 8. 기술

모아봄 서버와 같은 구성을 써서 코드를 옮기기 쉽게 해요.
- Next.js(App Router) + Prisma + Postgres(Neon), Vercel 배포(도쿄 리전)
- 서버 액션으로 저장 → 저장 후 `redirect`로 보던 화면으로 돌아가기
- PWA: `manifest`, 홈 화면 아이콘, 2차에 서비스 워커(웹 푸시)
- 모아봄과 **DB를 나눠요.** 한 DB를 같이 쓰면 가계부 쪽 변경이 이 앱에 영향을 줘서요. 옮겨 오고 싶으면 2차의 '모아봄에서 가져오기'로 한 번만 복사해요.

## 9. 단계별 범위

| 단계 | 내용 |
|---|---|
| **1차 (MVP)** | 시작 화면, 홈, 이벤트 리스트·캘린더, 이벤트 상세(보기), 이벤트·할 일·메모·돈 낼 날 작성 화면, 20개 기본 이벤트와 추천 일정·추천 할 일, 카카오 로그인/비밀번호, 체크한 사람 기록 |
| **2차** | 웹 푸시 알림, 메모 사진 첨부(스케치의 '메모(사진)'), 모아봄에서 이벤트·할 일 가져오기, 캘린더 내보내기(.ics → 구글·애플 캘린더) |
| **3차** | 업체 후보 메모(업체명, 출처, 상태), 하객 수 메모, 이벤트 순서 끌어서 바꾸기 |
